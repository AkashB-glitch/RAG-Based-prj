About PermRAG
Permission-Aware Multi-Tenant Retrieval-Augmented Generation
GitHub Repository ↗

The Problem: Relevant ≠ Authorized. In enterprise organizations, documents contain confidential data partitioned by role and tenant. Conventional RAG architectures retrieve information based on semantic relevance, risking prompt injection and data leakage if private documents are ingested into LLM prompts.

The Solution: Database-Enforced Defense in Depth. PermRAG enforces authorization at the database retrieval boundary using PostgreSQL Row-Level Security (RLS). Unauthorized chunks are blocked before scoring, reranking, and generation.

The Four Operational Security Invariants
  • RERANKER_INPUT ⊆ AUTHORIZED_RETRIEVAL_RESULTS
  • UNAUTHORIZED_CHUNKS ∩ RERANKER_INPUT = ∅
  • UNAUTHORIZED_CHUNKS ∩ LLM_CONTEXT = ∅
  • CITED_SOURCES ⊆ FINAL_LLM_CONTEXT

Evaluation Scope & Integrity: Evaluated on a 102-query gold evaluation dataset with 27 adversarial attack vectors, PermRAG achieved 0.00% unauthorized retrieval, 0.00% reranker input leakage, 0.00% LLM context leakage, and a 45.2% reduction in context window tokens.
